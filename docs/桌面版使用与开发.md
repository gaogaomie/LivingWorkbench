# 日常集桌面版

桌面版使用 Electron 承载现有 React 页面，独立进程运行 Fastify 和 SQLite。无需部署线上服务；DeepSeek 解读仍需要联网。

## 使用

首次启动可选择：

- 创建本地账号：设置用户名及至少 8 位密码，随后使用此账号登录。
- 导入已有工作台：选择包含 `data/daily-life.sqlite` 和 `uploads` 的项目目录。程序使用 SQLite 备份接口生成一致快照，复制附件，并导入该目录 `.env` 中的 DeepSeek 配置。原目录保持不变。导入前暂停旧工作台的写入操作，避免数据库快照和附件目录之间出现时间差。

导入仅在桌面数据库尚无账号时允许，不覆盖已有桌面记录。导入后使用原账号密码登录。已有桌面数据迁移使用应用内备份导入/导出流程。

默认数据目录：

- macOS：`~/Library/Application Support/DailyLifeWorkbench/`。
- Windows：`%APPDATA%\DailyLifeWorkbench\`（一般为 `C:\Users\用户名\AppData\Roaming\DailyLifeWorkbench\`）。

- `storage/daily-life.sqlite`：账号、记录、设置。
- `storage/uploads/`：附件。
- `storage/backups/`：备份。
- `settings.enc`：系统安全存储加密的 DeepSeek 配置和桌面会话密钥，不应复制到其他电脑使用。

应用菜单「日常集 → 设置…」可以修改模型、替换或清除密钥；留空保留已有密钥。「打开数据文件夹」可以定位数据。macOS 关闭窗口后应用保留在 Dock，使用 Command+Q 完整退出并关闭本地服务。

Windows 通过窗口顶部「日常集」菜单或 `Ctrl+,` 打开设置；关闭全部窗口后退出应用并关闭本地服务。安装程序为当前用户安装，可选择目录，并创建桌面及开始菜单快捷方式；卸载不会主动删除上述数据目录。跨电脑迁移请使用应用备份，不要复制 `settings.enc`。

升级安装包不替换上述数据目录。电脑之间不会自动同步。首次导入的是副本，此后 Web 版和桌面版分别保存数据。

## 开发和打包

需要 Bun 1.3.6、Node 24 和对应平台的原生构建工具。macOS 使用 Xcode Command Line Tools；Windows 使用 x64 Node/Bun，若原生模块需要从源码编译，还需要 Python 和 Visual Studio Build Tools 的「使用 C++ 的桌面开发」组件。普通使用者安装应用后不需要这些工具。

```bash
bun install
node node_modules/electron/install.js
bun run desktop:deps
bun run desktop
```

桌面原生依赖单独放在 `apps/desktop/runtime/node_modules`，不会把 Web 后端的 SQLite 模块重编译成 Electron 版本。`desktop:deps` 使用该目录的 npm 锁文件安装，再仅重建需要 Electron ABI 适配的 `better-sqlite3`；`argon2`、`sharp` 使用其 N-API 预编译文件。

```bash
bun run package:desktop
```

默认按当前系统和架构打包：macOS 生成 DMG，Windows x64 生成 NSIS 安装程序，输出到 `apps/desktop/release/`。打包会重新安装桌面运行依赖并重建 SQLite 模块，避免混入其他系统的原生文件。

也可以明确指定目标（必须在目标系统运行）：

```bash
bun run package:desktop:mac
bun run package:desktop:win
```

Windows 产物：`apps/desktop/release/DailyLife-0.1.0-windows-x64-setup.exe`；解包应用为 `apps/desktop/release/win-unpacked/DailyLife.exe`。当前 Windows 仅支持 x64，不提供原生 ARM64 或 32 位包。macOS 保留 x64/arm64 构建入口，仍需在对应架构机器安装依赖并测试。不支持在 Mac 上交叉打包 Windows。

Windows 安装包尚未配置代码签名，可能出现未知发布者或 SmartScreen 提示；公开分发前应配置自己的 Windows 代码签名。不要把证书或密码提交进仓库。

`.github/workflows/desktop-windows.yml` 在 Windows runner 上执行类型检查、桌面单元测试、打包及解包应用的真实 Electron 测试，通过后上传安装包；也可从 GitHub Actions 手动触发。不自动发布 Release。此流程仍需实际运行成功后，才能确认 Windows 验收通过。

Windows PowerShell 下验证解包应用：

```powershell
$env:DESKTOP_EXECUTABLE = (Resolve-Path 'apps/desktop/release/win-unpacked/DailyLife.exe').Path
bun run test:desktop:e2e
```

测试覆盖中文/空格数据路径、创建账号、登录、重启、加密文件和服务访问隔离，Windows 额外验证关闭窗口后退出。安装器交互、升级和卸载保留数据仍需 Windows 人工验收。

当前配置生成未进行 Apple Developer 身份签名和公证的本地自用版本。公开分发前需要配置自己的签名证书及公证凭据。不要把凭据或个人 `.env` 放入安装包。

仅打包 runtime 中的编译结果及运行依赖，不包含源码目录、个人数据库、附件、备份或密钥。

## 验证

```bash
bun run --cwd apps/desktop typecheck
bun run test:desktop
bun run test:desktop:e2e
bun run lint
bun run check:backend
bun run test:web
bun run test:e2e
```

Electron 测试使用临时目录和测试账号，覆盖首次设置、真实本地服务登录、重启后保留数据、退出后关闭端口，以及普通浏览器不能访问桌面服务。

验证实际打包的应用（当前 x64 产物）：

```bash
DESKTOP_EXECUTABLE="$PWD/apps/desktop/release/mac/日常集.app/Contents/MacOS/日常集" bun run test:desktop:e2e
```

桌面测试结果位于 `apps/desktop/test-results/`，与 Web 测试分别保存。

## 安全与实现边界

- Fastify 仅监听 `127.0.0.1`，每次启动使用系统分配的空闲端口。
- 本地所有请求需要仅由桌面会话注入的随机访问令牌；现有账号、Cookie、Origin 和 CSRF 校验继续生效。
- 工作台页面没有 Node 权限或配置 IPC 接口；设置窗口只暴露固定操作，并校验发送窗口和主 frame URL。
- 页面启用 sandbox、contextIsolation 和内容安全策略；拒绝新窗口与跨源页面导航。
- 用户没有配置 AI 或服务不可用时，沿用明确标记的本地规则摘要。
- 当前没有自动更新服务；可以手动安装新版并保留数据目录。
